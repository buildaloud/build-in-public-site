## Precedents

- 2026-07-13: Scout's H2s stay punchy and voice-first, not literal keyword matches. Confirmed by reading the published `2026-07-21-hired-a-team-of-specialists.md`: targetKeyword "claude code subagents instead of one prompt" never appears verbatim (or as a tight variant) in any of its 5 H2s ("The giant-prompt failure mode", "What a specialist actually is", etc.) — the keyword lives in title/meta/opening paragraph instead, and headings are left free to be punchy. Do not gate/flag an outline or draft for lacking the exact target-keyword phrase in an H2 when the opener + title + meta already carry it; that would push toward keyword-stuffed slop this project has already rejected. Outline-mode check should instead verify the `keyword` field (metadata) is mapped to the opener + at least one H2-worthy beat — that's sufficient.
- 2026-07-14/07-15: On rewrite posts, a PINNED title/description can arrive as a YAML *comment* near the top of the outline (not a schema field — `outline-schema.ts`'s `OutlineSchema`/`ParagraphNodeSchema` define no `title`/`description` fields at all; frontmatter is orchestrator-owned at the Assemble step). Treat a comment-carried pinned title/description as already-vetted and locked — do not flag its length/placement, and never propose an edit to it, even if it sits outside the "ideal" 50-60/140-160 windows (e.g. a 42-char title carried forward unchanged is fine when the outline explicitly says so). Same rule extends to draft-mode review of bare body prose with no frontmatter block at all (pre-Assemble artifact, e.g. a "suggested meta description seed for Assemble" comment in the outline's `pinned` section): skip title/meta length checks entirely rather than guessing — those fields don't exist yet in the artifact under review.
- 2026-07-15: When a beat's own `gateGuidance` explicitly warns against padding (e.g. a short "boring by design" Deploy beat), a mapped keyword that's fully absent from that beat is a light-touch nit only — propose a minimal same-length phrasing swap (a few words, not a new sentence), never a padded insertion that fights the beat's brevity intent.
- 2026-07-16: Confirmed on `2026-07-23-teaching-a-robot-to-balance-my-game` rewrite: when a secondary keyword is mapped to two adjacent beats, the outline's own `gateGuidance` can explicitly assign the literal-phrase placement to only ONE of the two beats and tell the other to use a synonym/pronoun instead ("don't repeat the exact phrase again here; call it 'the rig'/'the simulation'"), specifically to avoid the phrase reading as stuffed across adjacent sections. Don't flag the second beat for "missing" the secondary keyword when its own gateGuidance explicitly routed it elsewhere — check per-beat gateGuidance before flagging a keyword-coverage gap, not just the beat's `keyword` field in isolation.
- 2026-07-16: New check worth doing every draft-mode pass — cross-reference each beat's `rendersAsProse` flag against what the draft actually rendered. A beat marked `rendersAsProse: false` (meant to land as a bulleted list — e.g. an enumerated roster of bots/strategies) sometimes gets flattened into flowing prose sentences in the draft. That's a real scannability/snippet-worthiness loss for an informational-intent post (lists rank for list-style SERP features) and is worth an apply-ready elevation converting it back to a list, quoting the exact prose sentences to replace. Not every `rendersAsProse: false` beat needs this treatment, though — if the beat carries protected/quoted emotional-core lines (e.g. a "turn" beat with a required verbatim punchline), leaving it as prose is usually the right call for narrative flow; only push the list conversion on low-stakes enumerable-fact beats (bot rosters, feature lists), not on beats gateGuidance marks as carrying the post's emotional core.
