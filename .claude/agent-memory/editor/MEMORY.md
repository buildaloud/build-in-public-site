## Known recurring failures (seeded 2026-07-15 from measured run data)
- 2026-07-15 — You RE-INTRODUCE tone tells while applying edits. Run
  score-file.ts post-edit on the FULL assembled draft/outline, not just the
  edited spans (em-dashes get counted everywhere incl. comments/link
  titles); if it fails, sweep the whole text for remaining tells.
- 2026-07-15 — Performative register is banned (blog-drafter-pitfalls §7):
  no trailer fragments, dramatic inversions, or sales cadence, even if the
  finding's suggested fix is punchier.
- 2026-07-15 — CORE RULE: reviewer replacement/insert text (GATE, ADVISORY,
  AUTO-APPLY alike — GATE text is NOT pre-cleaned) almost always carries a
  fresh em-dash, incl. parenthetical pairs, in draft prose AND outline
  fields (gateGuidance/intendedBeat/facts). Reflow to colon/period/parens
  before landing, never pass through verbatim. Leave pre-existing em-dashes
  in untouched spans alone; deleting a flagged span clears its dashes free.
- 2026-07-15 — ADVISORY edits can reintroduce a pattern a GATE edit in the
  SAME round just removed — check every advisory against this round's own
  gate fixes, not just prior-round patterns, before applying.
- 2026-07-15 — grill-me: a fix can "land" textually while failing
  semantically — treat a synthesis landing-check as a priority re-fix. Edit
  the prompt's pasted "current draft," not the file on disk — can differ.
  Re-read neighbor edits after a batch; two safe alone can collide.
- 2026-07-15 — alt-text-seo: for a claim needing a real count, check the
  actual source rather than writing what the outline assumed.
- 2026-07-15 — which-claude-model: multiple nodes can share an identical
  short anchor quote — pair it with the node's own keyword/topic field.
  ai-automation-stack: a repeat GATE missing across rounds usually means a
  tighter anchor quote, not a tooling bug.
- automate-blog-publishing-schedule — locate edits by matching quote text
  verbatim, not the bracket label (labels can misname the field/beat); a
  mid-field insert-after goes right after its own field, not before, when
  the replacement is a new sibling. A technical-honesty "elevation"
  (verified-wrong number) is worth applying even filed as "for your
  consideration" — grep the real data yourself, don't trust the number
  either edit proposes. Round 2: when AUTO-APPLY/ADVISORY quotes overlap,
  apply only the one marked superseding; nearly every replacement string
