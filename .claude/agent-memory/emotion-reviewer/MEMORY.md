## General cross-project patterns

- **"Real X, real Y" intensifier stacking**: a triple (or double) "real"-prefixed noun phrase used to sell stakes instead of letting the concrete facts (numbers, a named file path, a scored delta) carry them — reads as an inserted emphasis crutch, not earned feeling. Confirmed recurring across at least two different posts (alt-text-seo-post order 7, which-claude-model-post's Haiku-backdoor beat) — flag every time it appears, don't wait for a second occurrence on the same post to treat it as real.

- **Bookend device, not dilution**: when a beat's aphoristic line appears both as an H2 heading and echoed in the closing body sentence, that's a deliberate stronger device — don't flag the double-occurrence. Only flag if the line is missing from the body prose entirely (heading-only doesn't count as "landed").
- **Two-consecutive-clean-passes rule**: once a beat's protect-verbatim `gateGuidance` (or the protected line itself) survives 2 consecutive passes unchanged, downgrade to spot-check/informational rather than a full re-flag every round — but keep spot-checking; a clean streak doesn't retire a historically sticky beat (see order 13 above).
- **Diff the full sentence, not just the opening words**: a protected line can survive its first clause while quietly losing a trailing clause that carried the concrete, checkable half of the point.
- **Low-point check for outlines**: this project builds in a correction-turn and a cost/honest-limit beat by default — before flagging "no beat admits a cost, doubt, or failure," check those two beat types first; the fix needed is usually sharpening from abstract/industry-stat to felt/first-person, not adding a beat from scratch. The felt admission sometimes lands in a `facts` bullet instead of `ourTake` — check both before flagging.
- **Redundant restatement pattern**: watch for a protected/strong line surviving intact but immediately followed (or preceded) by a flatter sentence that just restates the same point — the duplicate dilutes the landing even when the protected line itself is untouched.

- **"No exceptions" trailing crutch**: an ourTake or claim sentence that lands a real stance and then tacks on "no exceptions" (or equivalent absolute-qualifier tail) as a bureaucratic-sounding reinforcer instead of a new concrete beat. First seen which-claude-model-post orders 3/7 (2026-07-15); flagged on rate-limiting-an-llm post order 1's ourTake at outline stage 2026-07-16 — resolved. By the draft-mode pass (2026-07-16), order 1's ourTake ("Rate limiting an LLM API sits on the launch checklist right next to the feature itself.") carries neither the "no exceptions" tail nor the milder "same line item, same priority" stand-in — clean. Cross-project pattern confirmed; keep flagging on sight elsewhere.

- **SEO-keyword parenthetical stapled onto a design-rule sentence**: a clause that inserts the paragraph's target `keyword` phrase verbatim into an otherwise plain-spoken sentence, breaking its rhythm and reading as flat-corporate-affect insertion rather than something a person would say. STILL PRESENT on a third draft-mode pass (2026-07-16): "Doing public chatbot cost control this way means stacking six unclever limits instead of trusting one clever one" — the keyword-as-gerund-subject move itself has now survived three separate edit passes untouched. The pattern isn't tied to one sentence position or wording — it's the keyword-as-subject/object move itself. Flag on sight regardless of position; do not treat a numeral or verb-form swap as a fix.
