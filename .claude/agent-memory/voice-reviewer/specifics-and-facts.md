# Concrete-specifics gate patterns (detail file for MEMORY.md index)

## Outline instructs a real-number lookup; draft ships the placeholder anyway
2026-07-15 (draft mode, "writing-alt-text-seo-accessibility") — when an outline's `facts`/`gateGuidance` explicitly instructs pulling a real number from an external source the drafter can check (e.g. "pull the exact count from `git log --oneline -- 'src/content/blog/*.md'`... so the sentence carries a real number instead of 'some'"), and the draft ships the placeholder language anyway ("a stretch carrying no alt attribute at all, and a separate stretch carrying placeholder filler" — no counts at all), that's a gate finding even though the reviewer itself may lack the tooling (git access) to produce the exact number. Flag it and instruct the editor to run the specified lookup and drop the real count in; don't let "I can't verify the exact number myself" become a reason to wave the abstraction through — the outline already did the work of specifying where the number lives. Follow-up 2026-07-15 (next draft, same post): fixed — draft now reads "9 of the seventeen carried an empty alt=\"\" that told a screen reader nothing... The other 8 shipped with a real description already in place," real counts in place of the placeholder. Confirms the fix holds (note: draft collapsed the outline's two-failure-state framing into one; that's a fact-check/outline-fidelity question, not a voice-axis gate, since the specifics bar — real numbers present — is met).
Regression 2026-07-15 (later draft, same post): slid back to the vague "some carried no alt attribute at all... and others carried placeholder filler" with zero counts. This spot doesn't stay fixed once confirmed — recheck it on every draft of this post, same as the burstiness/CTA spots below. Fix by restoring the confirmed 9/17-and-8 split verbatim (or a freshly git-log-verified split if the underlying data changed).
